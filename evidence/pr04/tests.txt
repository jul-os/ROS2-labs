## Проверка параметров (живой опыт)

```bash
# Запуск ноды
ros2 run patrol patrol --ros-args -r cmd_vel:=/turtle1/cmd_vel
# Частота до изменения
ros2 topic hz /turtle1/cmd_vel
# average rate: 10.000 ... 9.999
```

Допустимое изменение частоты 10 → 5 Гц:

```bash
ros2 param set /patrol publish_hz 5.0
# Set parameter successful
ros2 topic hz /turtle1/cmd_vel
# average rate: 5.003 ... 5.000  (min 0.199s max 0.201s)
```

Недопустимые значения (отклонены, старая частота 5 Гц сохранена, поток продолжается):

```bash
ros2 param set /patrol publish_hz 0.0
# Setting parameter failed
ros2 param set /patrol publish_hz -3.0
# Setting parameter failed
ros2 param set /patrol publish_hz nan
# Setting parameter failed: Wrong parameter type, expected 'Type.DOUBLE' got 'Type.STRING'
```

NaN-случай дополнительно подтверждён юнит-тестом `validate_publish_hz(float('nan'))`.

## Проверка дефекта (отключённая проверка частоты)

Временно отключена валидация `publish_hz` в `parameter_callback`, передано 0.0:

```bash
ros2 param set /patrol publish_hz 0.0
```

Реальный отказ в терминале ноды:

```
ZeroDivisionError: float division by zero
  File ".../patrol/patrol/patrol.py", line 109, in parameter_callback
    self.timer = self.create_timer(1.0 / self.publish_hz, self.timer_callback)
                                   ~~~~^~~~~~~~~~~~~~~~~
```

После возвращения проверки (git checkout + rebuild) значение 0 отклоняется, старая частота и поток публикации остаются прежними.
